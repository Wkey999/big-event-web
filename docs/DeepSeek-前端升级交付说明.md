# DeepSeek 前端升级交付说明（第一轮）

范围：首页 + 共享导航 + 文章卡片。未改路由、接口、后台、编辑器与游戏加载策略。

## 一、设计方向：编辑台（Editorial Desk）

把首页从「瀑布流卡片墙」改成「一份编好的版面」：一条头条 + 一条按阅读顺序排列的清单。

三条取舍：

1. **顺序优先于拼贴**。原瀑布流用 `id % 3` 估高、把文章塞进 4 个桶，阅读顺序是列优先的，第 2 屏以后基本靠运气。现在是一条正常文档流：头条 → 第 2 条 → 第 3 条，键盘 Tab 和肉眼扫描的顺序一致，也不需要任何测高脚本。
2. **没有封面就不装封面**。原设计用大号标题生成「编辑封面」，正文又重复一次标题。现在无图条目就是文字条目：标题放大到 19px、摘要两行，靠排版立住；有图条目才给 208×130 的缩略图。
3. **界面少说话**。删掉「在 BOOM 分享 / 有用的内容，真实的分享」这类口号卡和右侧三条伪话题，右栏只留真实功能：AI 检索、开始创作、来源说明。

视觉上只用一种材料：**顶部导航是磨砂玻璃（唯一一处 blur），内容区是一张纸**。没有卡片阴影、没有渐变装饰、没有滚动入场动画。品牌绿从 `#376b42` 压到 `#255b46`，只在频道名、激活态、焦点环上出现。

## 四、已验证

- `npm.cmd run build` 通过；`npm.cmd run check:build` 通过（62 个 JS chunk，最大 223.26 kB，编辑器与游戏仍为懒加载）。
- 1440×900、1280×860、1920×1080 三种宽度截图核对：无横向溢出，文字不挤压，右栏不塌陷。
- 频道切换：点击「开发实践」后 `h1`、计数、条目数同步为 6 篇，激活态正确。
- 文章跳转：`/read/:id` 正常渲染，导航「发现」保持激活，作者卡/互动区未受影响。
- 无图条目、英文长标题、外部来源（Vercel Blog / GitHub Blog）三种真实形态均有截图确认。
- 登录态失效：接口不可用时按现有逻辑跳转 `/login`，未出现白屏。

## 五、未验证 / 限制

- **真实后端未启动**（需要 JDK 21 + MySQL），本轮视觉核对使用本地只读 mock（端口 8080，脚本在工作区的 `_mock` 目录，不在仓库里）。真实数据的封面比例、超长标题、空频道仍需连真库复核。
- 点赞、收藏、曝光上报只做了「不重复挂载」的结构核对，没有连真库写入验证。
- AI 检索、创作页、后台三个与管理页仍为旧视觉，属于后续批次。
- 未测试 Safari/Firefox（`backdrop-filter` 已有 `@supports` 降级）。

## 六、下一批建议

1. 阅读页：正文行宽、目录、作者卡与互动区，与首页共用同一套 token。
2. 搜索页：去掉 `FIND SOMETHING WORTH READING` 这类全大写引导语，改成结果数与筛选的紧凑工具条。
3. AI 检索页：把「单次问答」讲清楚，弱化未实现能力的暗示。
