# Gemini / DeepSeek 前端设计对比任务

两个分支从相同的代码快照开始，使用同一任务，不要求两个模型互相模仿。

## 工作目录

- Gemini：`D:\workplace\VUE_CODE\big-event-web-gemini`，分支 `design/gemini`。
- DeepSeek：`D:\workplace\VUE_CODE\big-event-web-deepseek`，分支 `design/deepseek`。
- 原始前端：`D:\workplace\VUE_CODE\big-event-web`，保留作为日常开发目录。

只修改分配给自己的目录，不切换或覆盖另一个目录。两个目录是同一 Git 仓库的独立 worktree，共用历史和分支记录，但各有工作文件与暂存区。

## 可以原样发送给两个模型的任务

请先阅读本目录 `docs/Gemini与DeepSeek-前端升级交接.md`，该文档同时面向两个模型，使用相同的工程背景、功能边界和验收要求。

请为 BOOM 大事件内容社区升级 PC Web 前端。产品以社区为主，AI/技术内容为特色，同时容纳体育、游戏、科技数码；小游戏是次要入口。本轮集中升级首页、共享导航和文章卡片，必要时微调相关共享组件和样式，保证其他页面仍然可用。不要顺便扩展后台、改造后端或迁移技术栈。

请独立提出并实现一种视觉方案：重点改善内容扫描效率、无图资讯、长标题、信息密度和布局稳定性。允许改变现有绿色配色和瀑布流。使用现有真实 API、来源信息与交互，不增加假数据、假热榜或未实现的功能宣传。保留登录权限、搜索状态、点赞收藏和曝光记录等业务行为。不要读取或输出私有密钥，不发起付费模型调用。

先阅读和检查，再简要说明设计方向，然后实际修改代码。完成后运行 `npm.cmd run build` 和 `npm.cmd run check:build`；在环境允许时检查 PC 页面、频道切换、搜索、文章打开及登录状态。交付改动说明、验证结果和未验证项。不要自行推送、合并或部署。

## 对比方法

尽量使用相同任务和首轮修改范围，分别保留两个模型的实际配置、耗时和补充指导记录。模型版本、工具权限和上下文不同，结果代表这次方案，不等于对模型总体能力的排名。

比较：第一眼的信息层级、真实资讯的阅读效率、无图/长标题处理、社区感、功能是否退化、构建检查是否通过、代码维护成本。漂亮截图之外，也要检查真实操作。

需要同时预览时，在各自目录启动：

```powershell
# Gemini 目录
npm.cmd run dev -- --port 5174 --strictPort

# DeepSeek 目录
npm.cmd run dev -- --port 5175 --strictPort
```

每个目录需要自己的依赖。若没有 `node_modules`，根据锁文件执行 `npm.cmd ci`；不要从另一个工作目录复制生成的编辑器缓存。开发代理仍指向同一个本地后端，因此测试写入会作用于同一个数据库，两边不要同时修改同一条内容。不要改动服务器预览来比较初稿。
